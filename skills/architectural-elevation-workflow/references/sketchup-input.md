# SketchUp 与平面联合生成四立面

适用于 `.skp` 配平面 DWG、SU 模型截图配平面 DWG，或同时提供三者。输入资料均只读处理，独立保存出图和核对结果。生成立面时，出图前按[网站构件匹配与适配](library-components.md)查库，门窗优先。

| 输入 | 取证方法 |
|---|---|
| SKP 配平面 DWG | DWG 提供轴网、各层墙柱和洞口定位依据。项目 SKP 提供实际空间关系及造型匹配依据。按项目核定的来源逐樘取尺寸。造型按用户指定来源或库件匹配规则采用，逐构件登记与平面的差异及采用依据。 |
| SU 截图配平面 DWG | 分区识别可见构件类型和组合。可补充正、背、左、右的平行投影视图及屋顶俯视图。毫米尺寸、隐藏面及坡向按平面、标高和节点核定，缺证部分登记为推定。 |
| SKP、截图及平面齐全 | 截图用于核对当前方案、场景和外观。几何以原生提取和配准结果检查。截图与 SKP 不同版本时分别登记。 |

## 1 至 3 步的输入核查与配准

1. 确认资料版本、建筑方向、楼层、单位、室内零点和是否需要施工图标注。记录 SKP 与 DWG 的文件哈希。检查模型是否含隐藏备选方案、场景、地形、邻栋、人物、家具或截面切割，再确定取用的建筑实例和范围。
2. 用原生 CAD 实体核对平面。取至少三个分布明确的非共线对应控制点，例如轴网交点、墙外角或柱中心。使用其中的对应关系求平面刚性变换，并用独立点和控制边长度检查方向、比例及剩余偏差。另核对对应的±0.000、各层楼面和室外地坪。记录原坐标、采用变换及残差。单位换算与设计偏差分别核查。镜像、缩放或轴线错认须追查来源。
3. 按楼层、轴段和构件对应 SKP 实例路径与 DWG 句柄。核对墙皮及柱完成面、门窗宽高和窗台、真实进退、雨棚与阳台附着、屋面交接和各柱承托。记录两源值、差异、采用值与依据。保留已证实的斜墙、退台和实际尺寸。关键节点用平面、水平截面、竖向剖面和四向正投影核对，截图仅用于可见造型取证。

### 各层外露范围与遮挡

- 投影前用平面楼层清单逐层对读 SKP 的主体、独立组及嵌套实例，核对设计场景及有效地形。适用时核查地下室、半地下层、下沉院落、坡道、挡墙和外露台阶，并关联各层墙柱、洞口及楼板边。以楼面、实际完成地坪及坡道起止点核定高差和进退。
- 按方向在平面和关键剖面上判定各区段完整外露、局部外露或遮挡。把核定的建筑面及参与遮挡的地形、挡墙、坡道面置于同一几何模型计算。局部外露的洞口按真实遮挡面裁切。记录方向、楼层、平面句柄或模型实例路径、可见范围、遮挡来源和待核项。
- 更新后逐向回核实际应见构件和遮挡边，再反核平面宿主与位置。若外露范围变化，按[标注生成及继承修订](elevation-annotations.md#生成及继承修订)复核相关视向的标注及打印窗口。

### 原生 SKP 读取

用同版本或兼容的本机 64 位 `SketchUpAPI.dll`。Windows 下可通过 `scripts/extract_skp.py` 只读提取。下例为本机已验证的 API 位置，使用其他安装目录时传入实际 DLL 路径。

```powershell
python 'C:/Users/PC/.codex/skills/architectural-elevation-workflow/scripts/extract_skp.py' 'D:/项目/建筑.skp' 'D:/项目/工作/模型原生几何.json' --api-dll 'D:/SketchUp 2027/SketchUp/SketchUpAPI.dll'
```

提取结果含文件哈希、实例路径和持久 ID、构件/组名称、标签、隐藏状态、毫米世界坐标下的面外环和孔环、边端点、软边及平滑标志、邻接面 ID。用`实例路径 + 实体ID`定位，同定义多次插入须分别保留。叠乘嵌套变换后，原生英寸坐标乘25.4得到毫米。SKP 模板的显示单位另行核对。接口见 [SketchUp C API 模型读取](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/struct_s_u_model_ref.html)及[面与孔环](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/struct_s_u_face_ref.html)。

提取器使用文件保存的实体和标签可见状态。指定场景、动态构件、透明材质、解析曲线和活动截面须另行核验。`loops_mm` 保存面外环和常规内环，`attached_openings` 保存附着切孔数量，`opening_rings_mm` 保存经宿主实例变换的附着孔环。合成有效遮挡面时，核对常规内环、附着孔环和原生网格的覆盖关系。切孔可能接触外边或彼此相邻，应从有效面的布尔结果提取边界。已含孔的原生网格直接核验孔覆盖，避免重复扣孔。旧快照只有切孔数量时重提取，附着孔边界未核定的宿主保持待核。`omitted` 列出未转入的图片、截面和三维折线。软边、隐藏边等原始数据保留供判断。原生读取失败、版本超出或只获得截图时，优先使用经核对的三维导出文件，并检查导出前后的单位、方向、构件及开孔。仅有图像时转入截图重建流程并标明证据范围。

### 样式与尺寸分别核验

- 生成或修订前逐樘确定门窗的尺寸与造型依据。用户指定按 SU 时，在指定范围内按已配准的原生实例实测洞口、窗台或门槛、框扇尺寸和分格。平面或节点与采用模型有差异时，保留两源定位、原值、采用值和采用理由。平面有洞口而指定模型缺项时，记录源图差异并按当前项目确认的范围处理。
- 台账分别记录完整洞口、框扇和套边尺寸，以及按实际遮挡裁切的可见宽高。用同尺度正投影核对形成尺寸的实际边界，保存重开后实测对应 CAD 几何。
- 按实例查证门窗框扇与分格、通层套边和层间装饰、柱基柱身柱头和包柱、线脚与天沟剖面及连续节点。区分洞口、窗框、装饰完成面及宿主边。天沟与檐口线脚、屋面饰边分别识别，是否存在和可见范围以原生实体及位置为依据。
- 从交付块及子实体追溯采用的库件、项目 SKP 原边和面，或从效果图确定的造型。核对框扇比例、非等宽分格、连续套边、柱段、线脚叠层与沟槽断面。库件尺寸按已核定的项目洞口和节点适配，记录原始几何、采用值及调整后保留的造型关系。
- 已查库且项目 SKP 缺少该构件时，继续用项目效果图识别。仍缺少依据的构造定位记录待核。平面已证洞口的边界可在协调稿中标明。
- 先做重点局部的原生模型与拟交付几何同尺度正投影对照，补做水平截面和竖剖以验证进深及承托。验证构件类型、数量、分段、组合、位置、比例及可见区间，再更新四向，逐件反核平面。只有独立保存重开的可编辑 DWG 才计入交付。

面环自接触或导入后难以直接构造有效面时，可加 `--mesh` 提取 [原生面的三角化](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/struct_s_u_mesh_helper_ref.html)。核对它与最终有效面及洞口一致后，按 `mesh.triangle_indices` 每三个索引从 `mesh.vertices_mm` 取一个三角面，只用于遮挡。修订过的面用修订后的几何重新划分。出图边仍从最终构件轮廓、折线及有依据的接缝提取。

### 窗台勒脚与门廊等节点协调

在出图前核对以下项目。局部核对通过后更新四向正投影，并在回核采用的造型、反核平面和重开 DWG 时检查受影响的构件与视向。

- **同层同类窗台。** 按立面、楼层和窗型分组，落地窗、普通窗、高窗各组内尽量统一窗台。以同层楼面为基准量核实际洞底，区分窗台、框底和套边底。统一采用值后联动洞口、窗框、窗套及相邻墙面。有依据的标高差或平面与 SKP 冲突逐樘记录原值、采用值和理由。
- **勒脚与窗套接顺。** 逐处核对勒脚压顶顶面、窗套底边的标高和进深，按剖面协调应接合处的实际接触和收口。检查连续压顶与窗套及相邻柱脚的过渡，避免窄缝、错台或穿线。有依据的构造缝按原节点表达。
- **同排门廊柱与柱脚。** 以同一完成面控制同排柱身前缘，在平面和柱身水平截面量核，再看侧立面是否出现无依据的前后重边。柱脚逐根对照 SKP 原生轮廓、分段和承托，核查柱基、下垛、外挑压沿及台阶或地坪的交接。调整柱位时联查同排柱、柱脚承台及相接栏杆、雨棚的定位。真实退进按本项目依据保留。
- **假老虎窗原生横格。** 核对拱框、底边、横格的数量、间距、端部及与宿主墙的关系。查找嵌套或独立实例中的原生可见边，逐条确认无邻接面的边是否属于横格。按实际内框和遮挡核对端部，避免漏格或墙顶线穿过拱口。经确认的横格作为构件线表达，独立于屋面填充。

窗台和勒脚标高、柱位和承台尺寸、横格数量与间距均由当前项目核定。历史案例尺寸仅用于本案追溯。

## 4 至 8 步的统一几何与出图

1. 将已经配准且核定采用的墙、洞口、柱、檐口等整理为最终面及有效邻接。按当前项目已确认的逐构件依据协调模型冲突，未解决的孔环、尺寸和样式保持待核，相应图纸按协调稿交付。场景选取、有效遮挡面、真正洞口、屋面坡折及曲面轮廓先核定。原模型瓦纹、离散网格、辅助线和场景人物从建筑看线提取中剔除。按现行规则从最终可见坡面独立生成瓦纹填充。保留已证实的造型轮廓和构造线。
2. `scripts/project_orthographic.py` 的 `project_four(faces, edges, audit={})` 可批量计算四向可见线，依赖 NumPy、Shapely 2。输入为毫米局部坐标，X 向正立面右方，Y 向建筑内部，Z 向上。`faces` 为核定的 `loops_mm`（外环在先，孔环在后），可用 `occludes=False` 表达已核定的透空表达。`edges` 为从最终几何提取的候选直边，含 `points_mm`、来源 `id/path`，可用 `views` 指定视向。返回四向 `points_2d_mm`、原边及可见参数区间。调用时传入空字典 `audit` 可记录遮挡面、边和裁切区间。先按[最终几何与四向断线核查](geometry-topology.md)确定有效边及各向轮廓，再计算裁切。投影工具处理直边，解析曲线与复杂面按项目使用相应几何方法。
3. 根据项目确认的方向为四个视图命名。按实例组织线条，分别给窗、装饰柱及线脚等成块。依 [构件块导出](component-blocks.md) 清理、排版并输出可编辑几何。需要施工图标注时按 `architectural-annotation-rules` 读取立面标注规则和本项目约定。用本机 CAD 保存为 DWG 并重开验证。
4. 先按各向对照采用的库件、项目 SKP、SU 截图或效果图，补齐或纠正构件。更新后逐层逐轴反核 DWG，检查洞口、墙垛、柱脚、檐口和进退实测值。造型或定位改动重复这两次回核。四向分别检查遮挡、断点和来源。交付记录包括源版本、配准控制点、两源冲突、取用范围、构件索引及校核结果。
