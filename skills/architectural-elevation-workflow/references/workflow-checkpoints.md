# 阶段记录与检查

按任务选模式，不增加任务外图纸：geometry用于生成或修订几何；annotations用于已有立面仅深化标注；review用于只读复核。

记录文件放项目工作目录。顶层字段为 `mode`、`views`、`sourceFiles`、`drawingFile`、`steps`。geometry模式另含 `geometryFile`，指向已提取的最终几何快照。每个文件记录 `path` 和实际文件的 `sha256`，相对路径以记录文件所在目录为准。views从项目要求和源清单确定，不能用已生成的图倒推。

## 阶段顺序

| 模式 | 顺序 |
|---|---|
| geometry | sources → geometry → shape-review → plan-review → reopen → drawing-review |
| annotations | sources → annotation-review → reopen → drawing-review |
| review | sources → drawing-review |

`steps`为按实际工作次序填写的数组。每项含 `id`、`status`（passed/pending/failed）；通过项含实际 `evidenceFiles` 文件记录，除sources外含所核 `views`。未完成项记录楼层、部位及原因 `reason`，不编造证据凑齐。

shape-review回核采用的库件、模型或效果图，修正后更新最终几何，再以更新稿做plan-review。geometry、shape-review和plan-review的 `geometrySHA256` 都绑定最终几何快照。shape-review、plan-review、annotation-review及只读模式的drawing-review，分别在本阶段的 `sourceFiles` 列出实际核过的来源路径及当时的SHA256。即使顶层清单已换成新版，检查器也能检出沿用旧版的阶段记录。按受影响范围重核。纯排版改动只重做受影响的标注、重开和图面检查。

annotation-review、reopen、drawing-review的 `drawingSHA256` 绑定最终DWG。证据文件应包含技能已有要求的逐实例来源、测点/测值、原生对象和视向结果；计数或“已检查”文字不能代替实际核对。文件保存并重开后再固定最终DWG指纹。

将本技能根目录解析为绝对路径 `$elevationSkill`，从项目目录运行：

```powershell
python -B -X utf8 "$elevationSkill/scripts/check_workflow.py" "<项目阶段记录.json>"
```

检查器核阶段顺序、任务视向、文件存在与指纹、最终几何及DWG关联，不判断构件造型正确与否。阶段记录检查通过不等于CAD图纸通过。

项目按已有约定允许协调稿或阶段预览时可加 `--allow-pending`：仍保留pending/failed和原因，complete保持false；不改变现有正式交付要求，不把待核稿称为全项验收通过。只读复核不要求为凑步骤改写原DWG。

## 旧脚本复用与独立验收

只执行入口规定的三项要求，沿用上文已有阶段记录。项目来源、实例和测点信息复用现有清单；工具能读取的结果自动汇入，只有实际歧义交由资料核对或必要澄清。

1. **统一生成入口。** 按[正式运行入口](runtime-consistency.md)绑定当前规则、共用源码、构建和实际加载版本。项目输入重新读取；历史项目复制和直接构建入口退出正式链，不以文件名或另一个项目已通过替代检查。历史业务命令许可仍按本次适用授权执行。几何核定与原生生成、原生验证与全项图纸验收分别记录。
2. **生成前核准关键依据。** 在现有来源清单核定屋面采用版本和实例、门窗实际控制边及宿主、项目零点和单位变换。屋脊识别见[屋面专项](geometry-topology.md#屋面来源与屋脊识别)，门窗测点见[标高专项](window-symbols-and-local-levels.md#门窗控制边与标高取值)。复用快照先核源指纹，来源或几何变化后重算受影响的关联、投影和标注。旧坐标、固定楼层、屋脊高度及实例ID不作为新项目默认值。已有确认直接执行；无法确定的部位保留待核，其他有据部分继续。
3. **交付前执行固定检查。** 在本次适用视向内，从原资料独立读取或复量，再与保存重开的实际DWG对照以下项目。已有修订只检查本次及同类问题影响范围；发现问题修正后重查对应项，待核项保留原因及定位。经项目约定可交阶段稿时注明未完成范围，不能称全项通过。

| 固定检查项 | 通过依据 |
| --- | --- |
| 来源与平立面对应 | 核当前版本、单位、方向、采用依据及生成后的平面反核，源冲突和授权协调分别登记。 |
| 构件完整与造型 | 核任务涉及的墙柱、门窗、屋面、雨棚、栏杆、台阶等数量、位置、进退、承托及连接；柱脚与实际地坪/承托对应。 |
| 屋面及屋脊 | 与采用来源的脊谷、端点、走向、坡面交接及控制高度对应，区分脊饰顶，未混入旧稿或网格边。 |
| 门窗与符号 | 核洞口尺寸、框套接缝和分格；固定玻璃符号居中，开启符号对应类型与方向，逐扇无漏标、重复和混标。 |
| 施工图标注 | 核尺寸测站、连续闭合及文字排布，轴号轴位、全部适用标高、图名和比例。门窗标高对应实际上下口及零点且无引线/测量接线；主标高基线按现行要求连接。 |
| 可见线 | 核漏线、重线、碎线、意外断口、穿线和误遮挡，保留有来源的构造接缝及真实遮挡。 |
| 图层、填充与块 | 展开嵌套核有效层色和线型、瓦纹实际边界及遮挡，核块参照、共享定义、对应实例和可编辑性。 |
| 保存与交付 | 核原生对象重开保真、源图保护、排版和实际打印范围及待核状态；仅交付本次要求的格式。 |

`check_workflow.py`核阶段、文件及版本关联；生成预期表、AUDIT和实体计数用于一致性检查。来源、控制边与实际图形仍需上述核对，不将记录检查通过等同图纸通过。实现改动时复查受影响的已知失败样例；单个项目执行时不额外要求搭建全套测试平台。
